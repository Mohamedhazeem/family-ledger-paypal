# ADR-0009: Append-only LedgerEvent audit trail (no update/delete in code)
- Status: Accepted
- Date: 2026-11-06
- Deciders: Tech Lead, Founding Engineering
- Spec refs: Part C §9 (`LedgerEvent`), Part B §Steps 10, 3
- Supersedes: none

## Context
Plan versions immutable; payout lifecycle must be auditable without rewriting history.
## Decision
`LedgerEvent` table (`actorType`, `eventType`, `payloadJson` allowlisted, `createdAt`) — append-only from application code.
## Consequences
### Positive
- Trust, replay, filtered timelines for both parties.
### Negative / trade-offs
- Storage growth; allowlist discipline.
### Risks & mitigations
- Secret leakage — allowlist payloads, redact PII.
## Alternatives considered
Mutable audit columns — rejected: rewritable history.
## Implementation guardrails
- MUST NOT issue UPDATE/DELETE on LedgerEvent in code; MUST NOT include secrets.
## Verification
- Integration tests: events created on each milestone; update/delete attempts fail in code review + test.
