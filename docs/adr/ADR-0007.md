# ADR-0007: Invitation security: 32-byte random tokens, SHA-256 at rest, expiry, revocation, rate limiting
- Status: Accepted
- Date: 2026-11-06
- Deciders: Tech Lead, Founding Engineering
- Spec refs: Part C §13, §9, Part B §Step 4
- Supersedes: none

## Context
Beneficiary portal is public link; tokens must not leak, expire, be reversible.
## Decision
Generate ≥32-byte random token via Node crypto; store SHA-256 hash only; default 7-day expiry; allow revoke; repeated reads until expiry; rate-limit lookup/mutation.
## Consequences
### Positive
- Leak-resistant; copyable link works without email.
### Negative / trade-offs
- Lost token = new invitation; ops overhead.
### Risks & mitigations
- Enumeration — rate limiting + hash lookup.
## Alternatives considered
JWT in URL — rejected: recoverable, harder to revoke.
## Implementation guardrails
- MUST NOT store raw token; MUST expose only shareable data on beneficiary portal.
## Verification
- Unit/integration: hash/expiry/revocation/rate-limit tests.
