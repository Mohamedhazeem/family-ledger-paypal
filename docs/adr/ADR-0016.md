# ADR-0016: Hexagonal/Ports-and-Adapters seam for all third-party integrations (AI, PayPal, AG Studio, email, auth, DB) to guarantee swappability
- Status: Accepted
- Date: 2026-11-06
- Deciders: Tech Lead, Founding Engineering
- Spec refs: Part C §7 (all integrations), Part D §15 (Render/APIMatic)
- Supersedes: none

## Context
Every third-party (AI, PayPal, AG Studio, email, auth, DB) must be replaceable without touching business rules.
## Decision
Define `Port` interfaces in `src/services/<name>/`; adapters implement ports; env vars select adapter; services import only ports; dependency direction enforced.
## Consequences
### Positive
- Vendor swap by config + new file, not refactor; testable with mocks.
### Negative / trade-offs
- Interface design overhead.
### Risks & mitigations
- Overspecification — keep ports minimal, DTO-based.
## Alternatives considered
Direct SDK calls — rejected: lock-in, violates AGENTS §4.
## Implementation guardrails
- MUST NOT import adapter SDKs in business services; MUST validate adapter output with Zod; MUST document new adapter via `docs/agents/` + ADR amendment.
## Verification
- Swap playbook test: add Mock adapter and run suite without caller change.
