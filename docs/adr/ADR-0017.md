# ADR-0017: Clean Architecture: Entities, Use Cases, Ports, Adapters, Frameworks
- Status: Accepted
- Date: 2026-11-06
- Deciders: Tech Lead, Founding Engineering
- Spec refs: Part C §7–§8 (stack, structure), Part C §11–§12 (PayPal/AI boundaries), ADR-0011, ADR-0016
- Supersedes: none

## Context
FamilyLedger must stay swappable (AI/PayPal/AG Studio/DB/auth/email) and testable for a 6-day build. Current hexagonal ports are a subset of Clean Architecture. To avoid framework lock-in bleeding into business rules, adopt explicit Clean Architecture rings.

## Decision
Clean Architecture with four rings, dependency rule pointing inward:

```
Frameworks & Drivers (Next.js, Tailwind, Prisma, PayPal SDK, OpenAI)
        ↓ uses
Adapters (PayPalSandboxAdapter, PrismaPostgres, OpenAiAdapter, AgStudioAdapter)
        ↓ implements
Ports (AiProvider, PayoutsPort, DisbursementRepository, AnalyticsPort, AuthPort, EmailPort)
        ↓ orchestrates
Use Cases (CreateDisbursement, SendPayout, AcceptInvitation, ...)
        ↓ operates on
Entities (Disbursement, PlanVersion, PlanItem, PayoutAttempt, LedgerEvent, MoneyValueObject, StateMachines)
```

- **Entities** (`src/domain/entities/`, `src/domain/value-objects/`): plain TypeScript, no framework/SDK imports. Hosts `PlanStatus`/`PaymentStatus` enums, invariants (money as BigInt minor units, plan≠payment independence), no receipts/surveillance fields.
- **Use Cases** (`src/application/use-cases/`): one class/function per vertical slice (`CreateDisbursementUseCase`, `ParseSupportIntentUseCase`, `AcceptInvitationUseCase`, `SendPayoutUseCase`, `GetPayoutStatusUseCase`). Orchestrate Entities + Ports. No Next.js/Prisma/PayPal imports.
- **Ports** (`src/application/ports/`): interfaces (`AiProvider`, `PayoutsPort`, `DisbursementRepository`, `AnalyticsPort`, `AuthPort`, `EmailPort`, `Clock`). Defined in application layer; implemented in adapters.
- **Adapters** (`src/infrastructure/ai|paypal|db|analytics|auth|email/`): Zod validation, SDK/Prisma calls, DTO mapping. Only place vendor packages are imported (`import 'server-only'`).
- **Frameworks & Drivers** (`src/app/`, `src/components/`, `src/lib/`): Next.js App Router Route Handlers (thin, validate→Use Case→presenter), Tailwind/shadcn/Lucide, Server Actions, `proxy.ts`. No business logic.

## Consequences
### Positive
- Business rules testable with in-memory ports (no DB/network/API key in unit tests); swap vendor by adding adapter + env var, not refactor; single deployable remains (ADR-0001).
### Negative / trade-offs
- More files/indirection; premature abstraction risk in 6-day window — keep ports minimal, DTO-based, one use case per slice per ADR-0013.
### Risks & mitigations
- God-file drift — 300 LOC limit + review checks; leakage — ESLint `no-restricted-imports` to ban `domain/application` → `frameworks/infrastructure` imports.

## Alternatives considered
- **Hexagonal only (ADR-0016)**: sufficient for ports but silent on Entities/Use Cases separation — now subsumed by this ADR (ADR-0016 remains valid as the Ports & Adapters facet of Clean Architecture).
- **Fat services without Entities**: rejected — invariants (money, state machines, consent independence) need a single pure home testable without mocks.
- **Microservices**: rejected — violates spec scope (no microservices).

## Implementation guardrails (what future code MUST/MUST NOT do)
- MUST keep dependency rule: `domain` ← `application` ← `infrastructure` ← `frameworks`. `domain` imports nothing internal; `application` imports only `domain` + `ports`.
- MUST put business invariants in Entities; MUST NOT put Next.js, Prisma, PayPal, OpenAI imports in `src/domain` or `src/application`.
- MUST map external DTOs in adapters with Zod; MUST NOT leak SDK types past adapters.
- MUST one Use Case per action; MUST keep Route Handlers thin (ADR-0011).

## Verification (tests or checks that prove this decision is respected)
- Unit tests in `domain`/`application` run with mock ports, no DB/network; `npx tsc --noEmit` + ESLint `no-restricted-imports` fails if dependency rule violated; swap-playbook test: new Mock adapter runs suite unchanged.
