# ADR-0002: Persistence: Prisma + PostgreSQL as single source of truth
- Status: Accepted
- Date: 2026-11-06
- Deciders: Tech Lead, Founding Engineering
- Spec refs: Part C §7, §9 (Database entities), Part F Day 1
- Supersedes: none

## Context
Disbursements, immutable PlanVersions, encrypted recipiency, `PayoutAttempt` idempotency, append-only `LedgerEvent` need one transactional store.
## Decision
PostgreSQL via Prisma ORM — schema, migrations, queries. Entities: Organization, User, Beneficiary, Disbursement, PlanVersion, PlanItem, RecipientInvitation, PayoutAttempt, LedgerEvent.
## Consequences
### Positive
- ACID, migration history, indexed queries for performance; one place for constraints (unique sender ids).
### Negative / trade-offs
- Migration discipline required; Prisma learning curve.
### Risks & mitigations
- N+1 queries — use Prisma `include`/raw aggregate views where needed; paginate registers.
## Alternatives considered
MongoDB / Firestore — rejected: relational constraints and aggregate analytics fit Postgres better.
## Implementation guardrails
- MUST use Prisma for data access; services depend on repository ports, not raw client (ADR-0016).
- MUST keep PlanVersions immutable; LedgerEvents append-only.
- MUST index status/date/programme columns for analytics.
## Verification
- `prisma migrate dev` + seed creates full scenario; unit/integration tests for constraints pass.
