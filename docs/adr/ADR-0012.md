# ADR-0012: Mock vs sandbox payment modes: visible badge, never conflated, judge demo must use real sandbox call
- Status: Accepted
- Date: 2026-11-06
- Deciders: Tech Lead, Founding Engineering
- Spec refs: Part C §11, Part B §Steps 8–9, Part E §16–17
- Supersedes: none

## Context
Local tests/local UI need mock; judge must see real PayPal sandbox call.
## Decision
Two explicit modes: `SANDBOX` (real Payouts call) and `MOCK` (local provider). Permanent `MOCK PAYMENT` badge whenever mock active. Never represent mock as sandbox transaction.
## Consequences
### Positive
- Honest demo, safe local dev.
### Negative / trade-offs
- Third adapter to maintain.
### Risks & mitigations
- Badge forgotten — UI component enforced + tested.
## Alternatives considered
Silent mock — rejected: deceptive, violates spec.
## Implementation guardrails
- MUST badge mock prominently; MUST track `paymentMode` on Disbursement; MUST fail judge demo if sandbox unavailable (Day-0 gate).
## Verification
- Both modes tested; badge present in Playwright screenshots.
