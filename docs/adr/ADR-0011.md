# ADR-0011: Service-layer pattern: thin Route Handlers, testable business services
- Status: Accepted
- Date: 2026-11-06
- Deciders: Tech Lead, Founding Engineering
- Spec refs: Part C §8, §3 architecture, Part F Day 1–4
- Supersedes: none

## Context
Business rules in handlers would be untestable and couple UI to SDKs.
## Decision
Handlers parse/auth/validate → delegate to `src/services/*` (single-responsibility) → typed response. SDKs only in adapters.
## Consequences
### Positive
- Unit/integration tested services without Next.js request objects.
### Negative / trade-offs
- Indirection for trivial CRUD.
### Risks & mitigations
- Logic leakage — code review checks handler LOC/behaviour.
## Alternatives considered
Fat handlers — rejected: untestable, god-files.
## Implementation guardrails
- MUST NOT put arithmetic/state rules in Route Handlers; MUST NOT import adapters in services.
## Verification
- Service tests run without HTTP framework; Playwright covers happy path.
