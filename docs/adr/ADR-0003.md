# ADR-0003: Money: integer minor units + decimal-safe conversion; floats banned
- Status: Accepted
- Date: 2026-11-06
- Deciders: Tech Lead, Founding Engineering
- Spec refs: Part C §7, §9 (`amountMinor`), §12 (AI money), Part B §Step 2
- Supersedes: none

## Context
Currency USD only; AI returns `amountText` strings; float math on money risks rounding errors.
## Decision
Store/hold `amountMinor` as integer/BigInt. Convert once at boundary with decimal-safe library (e.g. decimal.js) in `src/lib/money/`.
## Consequences
### Positive
- Exact arithmetic, testable conversion, no rounding drift.
### Negative / trade-offs
- Extra conversion layer; BigInt handling in UI.
### Risks & mitigations
- Float slip-through — banned APIs + ESLint rule + unit tests.
## Alternatives considered
Float dollars — rejected: rounding & audit failures. String money end-to-end — rejected: verbose.
## Implementation guardrails
- MUST NOT use `parseFloat`, `Number(amount)`, float `*100` or comparisons on currency.
- MUST validate ≥2-decimal, reject negative/non-decimal.
## Verification
- Unit tests: conversion, remainder/unallocated, over-total rejection, translation preserves amounts.
