# ADR-0014: Testing strategy: Vitest + Playwright + Postman, TDD loop
- Status: Accepted
- Date: 2026-11-06
- Deciders: Tech Lead, Founding Engineering
- Spec refs: Part C §7, Part E §17, Part B §18 demo
- Supersedes: none

## Context
Behavioural correctness for money, state, PayPal idempotency, AI validation outweighs coverage vanity.
## Decision
Pyramid: Vitest unit → service integration → Playwright E2E (11-step flow) → Postman collection. Red→green→refactor per feature.
## Consequences
### Positive
- Fast feedback, regression safety for hackathon demo.
### Negative / trade-offs
- Upfront test write time.
### Risks & mitigations
- Flaky E2E — sandbox + mock modes tested separately; deterministic fixtures.
## Alternatives considered
Tests after code — rejected: allows regressions.
## Implementation guardrails
- MUST write tests with feature; MUST cover explicit-amount, null-amount, no-split, sums, token, duplicate prevention.
## Verification
- Full suite green in CI; coverage tracked as behavior, not % target.
